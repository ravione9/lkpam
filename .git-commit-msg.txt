fix: web-proxy URL building, SSH enable/logout detection, RADIUS healthchecks

Three latent bugs surfaced by the failing test suite plus my new RADIUS
service:

* api-gateway buildUpstreamURL kept ":443" / ":80" in the rewritten URL
  (breaking SPAs that compare window.location.host) and dropped the
  target's base path (FortiOS "/ui", PAN-OS "/php"), so every static
  asset 404'd through the proxy. Now strips default ports via
  upstreamHost() and prepends the target base path when rest is an
  absolute device-root path.

* sshproxy cmdGate could not detect "enable", "logout", "exit", or any
  command at all when the device hadn't yet echoed the typed line back
  (Cisco often jumps straight from "en" to "Password:" without echoing
  "en"). Added a userTyped buffer accumulated in Write(), used as a
  fallback in currentCommand(). Also clear devLine when expectEnablePass
  is set so the device's "\r\nPassword:" reply doesn't trip the stale
  ">"-prompt reset path before the auto-inject can fire. Backspace
  (0x08 / 0x7f) now decrements userTyped correctly.

* RADIUS healthchecks were unreliable (Docker: nc -uz on UDP can't be
  trusted; k8s: tcpSocket probe pointed at port 8081 which lives in the
  auth pod, not radius). Switched both to busybox pidof on the
  radius-service binary.

All previously failing tests now pass: TestBuildUpstreamURL,
TestBuildUpstreamURLWithBasePath, TestCmdGateInjectsEnableSecret,
TestCmdGateAutoInjectOnlyOncePerEnable, TestCmdGateLogoutEndsSession.
