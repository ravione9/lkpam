How access works

SSH / CLI — after access is approved, connect via the PAM SSH proxy:

ssh -p 2222 … "user@#machine-id@host"

RDP (CyberArk-style) — PAM does not create a Windows user for each portal login. Instead:

  1. Admin registers the Windows server under Machines (connection type RDP).
  2. Admin creates a privileged account in Safes → Privileged Accounts linked to this machine (e.g. Administrator or _PAM_RDP). CPM rotates the password.
  3. User submits Request access → approver grants JIT access.
  4. User clicks Launch → Open in browser (recorded) — session is proxied through PAM/guacd and saved as a .guac recording. Or download .rdp + script for native mstsc (not recorded).

Select Windows Server below for the one-time onboarding script to create the PAM-managed local account on the target.

Tip: on the Machines tab, click Request access on a row, wait for admin approval, then connect.
